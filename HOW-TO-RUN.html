EximBill Sanity Kit

A Playwright Test framework that runs the daily EximBill sanity check by itself: it creates a transaction for each product, takes it through maker, validator and RFA approval to Mastered, checks Exception, FIRCO, GAPI and Enquiry, and writes the result into an Excel sheet with the same columns as the manual sanity sheet, plus a Playwright HTML test report with every step.

1. What is in the folder

Nothing needs to be installed. Everything the scripts need is inside this folder, and they use the Microsoft Edge browser that is already on every Windows PC.

2. One-time setup

  1. Copy the whole folder to the PC, for example to C:\EximBillSanity. Keep all files together. A short path without spaces is safest.
  2. Open settings.json with Notepad (right-click > Open with > Notepad) and change these lines for your environment. Keep the quotes and commas exactly as they are. 
    "environment": "PRE-SIT",                         <- name printed in the results
"url": "http://<server>:8080/EximBillWeb/",       <- the EximBill login page
"businessUnit": "ENBD",

"users": {
  "maker": "ANBU_MK",                              <- registers and does the maker steps
  "checkers": ["ANBU_VAL", "ANBU_AUTH"],          <- authorize in this order, one approval each
  "rfa": "RFARFIINTERVENE"                         <- approves RFA / RFI (Intervene)
},
"rfaFallbackToMaker": true,                        <- if the RFA user cannot log in, use the maker
"samePasswordForAllUsers": true,                   <- ask one password for all three users

"database": {
  "enabled": true,
  "user": "EXIMWFBK",                              <- a read-only database user
  "connectString": "10.2.3.21:1522/DENBDPDB",      <- host:port/service of the EximBill database
  ...
    Passwords are never written in any file. The scripts ask for them on screen each time (typing shows *).
  3. Double-click 0-SETUP-CHECK.bat. Type the EximBill password and the database password when asked. You should see: 
      [OK]   Node.js v22...
  [OK]   Microsoft Edge starts
  [OK]   EximBill login works for ANBU_MK
  [OK]   Database EXIMWFBK@...
All good. You can run the sanity scripts.
    If a line says [FAIL], see If something goes wrong.

3. Run the sanity check

  1. Clear the cache on the server first, as you do for the manual sanity (the sheet records "CACHE CLEAR = YES").
  2. Double-click the script for the product, for example RUN-IPLC.bat, or RUN-ALL.bat for everything.
  3. Type the passwords when the black window asks for them, and press Enter.
  4. Leave the PC alone. An Edge window opens and works by itself. Do not click in it or close it. It logs in several times, one user after the other:
    • Maker (e.g. ANBU_MK): Workflow Initialization > Register One Step, claims the task from Group Queue, loads the template, ticks the TBML box, does the Finacle limit check, answers any RFI, confirms the maker decision.
    • RFA / RFI Intervene (e.g. RFARFIINTERVENE): approves the compliance RFA (Decision > Approve).
    • Checkers, in the order of checkers in settings.json: ANBU_VAL claims the Checker task and releases it; when EximBill says "partially authorized and requires further authorization", ANBU_AUTH logs in and gives the next approval. Add or remove names in the list if your authorization matrix needs more or fewer levels.
    Then it waits for Auto Refresh / Auto Release to master the transaction and runs the enquiry checks.
  5. Wait for the summary at the end of the black window: RESULT: ALL PASSED or RESULT: SOME CHECKS FAILED, with the path of the Excel report. The test runner prints each test as it finishes (ok = passed, x = failed). One product takes about 10 to 20 minutes; most of it is EximBill and the auto release.
  6. Press any key to close the black window.

4. Read the results

The HTML test report

Double-click SHOW-HTML-REPORT.bat. Your browser opens the Playwright report (close the black window when you are done). It lists the tests of the last run:

  • 1. Maker, 2. RFA, 3. Checker, 4. Wait for Mastered, 5. Checks: one test per phase. If a phase fails, the next ones are skipped.
  • IPLC-01 (IPLC) sanity result and so on: one test per transaction. It is red when a sanity column is Not OK; click it to see which check failed and why, with screenshots. The Excel file and the log are attached to test 5.

The Excel report and other files

5. Check a transaction that already exists

Double-click RUN-EXISTING-REF.bat, type the product code (e.g. IPLC) and the reference (e.g. ENBDLC26007798). If the transaction is still waiting in the workflow, the script finishes the open tasks first; then it runs all the checks and writes the Excel sheet.

6. Run it on PRE-SIT (or any other environment)

Everything that is different per environment is in one file, settings.json. Double-click EDIT-SETTINGS.bat to open it in Notepad.

  1. Make a copy of the folder per environment if you want to keep DEV and PRE-SIT side by side, e.g. C:\EximBillSanity-PRESIT.
  2. Change these lines (keep the quotes and commas): 
    "environment": "PRE-SIT",
"url": "http://<pre-sit server or IP>:<port>/EximBillWeb/",
"businessUnit": "ENBD",
"users": {
  "maker": "<PRE-SIT maker user>",
  "checkers": ["<first checker>", "<second checker>"],
  "rfa": "<RFA/RFI intervene user>"
},
"database": {
  "enabled": true,
  "user": "<read-only PRE-SIT database user>",
  "connectString": "<db IP>:<port>/<service name>",
  "workflowSchema": "EXIMWF", "systemSchema": "EXIMSYS", "transactionSchema": "EXIMTRX"
},
    Use the same URL you type in Edge to open EximBill, ending with /EximBillWeb/. For the database, use the IP address rather than the host name.
  3. Save (Ctrl+S) and close Notepad.
  4. Check the test data for PRE-SIT (next section): customer IDs and template names must exist in PRE-SIT. Open each product screen once by hand, click toolbar Load, and note a template name that exists there.
  5. Run 0-SETUP-CHECK.bat. All lines must be [OK].
  6. Run RUN-IPLC.bat first. When it works, run the other products or RUN-ALL.bat.
Tip: "showBrowser": false in settings.json runs the browser hidden (faster, but you cannot watch it). Keep it true until everything works.

7. Test data in Excel, XML or JSON

The values used to create transactions come from data\testdata.xlsx (double-click EDIT-TEST-DATA.bat). One row = one transaction. Add rows to test more cases, for example two IPLCs with different customers or amounts.

ColumnWhat to put
Test IDAny unique name, e.g. IPLC-01. Run one row with RUN-TEST-ID.bat. It is copied to the result sheet.
ModuleIPLC, EPLC, IMCO, EXCO, GTEE or IWGT.
Run (Y/N)Y = included in RUN-ALL.bat and RUN-<module>.bat. N = skipped.
ProcessProcess Name exactly as in Register One Step.
Customer, CurrencyCustomer ID / CIF and currency for the registration.
AmountA fixed amount, or empty for a random amount (avoids the "Duplicate Data" check). Some templates carry a fixed payment split; then the amount must match the template (EXCO TEST = 6080).
TemplateTemplate from the toolbar Load list.
FillExtra fields by field name: NARR1=SANITY CHECK; REMARKS=test
DefaultsValues for "<Label> can't be empty" messages: Email Address=a@b.com
RemarksFree text, copied to the result sheet.

Empty cells take the value from modules\<module>.json. The second sheet "How to fill" in the Excel file repeats this table.

Using XML or JSON instead of Excel

Ready examples are in data\examples\testdata.xml and data\examples\testdata.json (same rows as the Excel file). Point settings.json at the file you want:

"testData": "data/testdata.xlsx",                 <- Excel (default)
"testData": "data/examples/testdata.xml",         <- XML
"testData": "data/examples/testdata.json",        <- JSON
"testData": "",                                   <- no data file: one case per enabled module file

XML format:

<tests>
  <test id="GTEE-01" module="GTEE" run="Y">
    <process>Create Outward</process>
    <customer>88888888</customer>
    <template>Sangeetha</template>
    <fill name="NARR1">SANITY CHECK</fill>
    <default label="Email Address">a@b.com</default>
  </test>
</tests>

To rebuild the Excel and example files from the module files: node\node.exe framework\make-testdata.js (this overwrites data\testdata.xlsx).

8. Change a product (module) setting

Each product has a file in modules\, for example modules\IPLC.json. Open it with Notepad:

{
  "code": "IPLC",                               <- product code (do not change)
  "name": "Import Letter of Credit",
  "menu": "Import Letter of Credit",            <- name of the product in the left menu
  "enabled": true,                              <- false = RUN-ALL skips it
  "process": "Issue Letter of Credit One Step", <- Process Name in Register One Step
  "customer": "88888888",                       <- Customer ID/CIF used to register
  "ccy": "AED",
  "amountFrom": 100000, "amountTo": 109000,     <- a random amount in this range
  "register": { "WF_VESSEL_CHK_FLG": "No" },    <- drop-downs on Register One Step (field name: shown text)
  "template": "IPLC_ISSUE_KAISER",              <- template picked with toolbar Load
  "fill": {},                                   <- extra fields: { "FIELD_NAME": "value" }
  "defaults": {},                               <- values for "X can't be empty": { "Email Address": "a@b.com" }
  "notes": ""
}
  • Different customer or template? Change customer or template. The template must exist in the toolbar Load list of that screen.
  • "... can't be empty": the script fills these automatically with a test value. To choose the value, add it under defaults using the exact label from the message.
  • TBML tasks: Vessel check flag = Yes on Register One Step creates a TBML Maker task, and the TBML flag on the transaction (e.g. Create Collection) creates a TBML RFA. The kit registers with "WF_VESSEL_CHK_FLG": "No" (in "register"); change it to "Yes" to test the TBML flow. Empty drop-downs on Register One Step that are not listed in "register" get their first value.
  • RFI "Limit expired": the customer's limit has expired, so EximBill raises an RFI. The script answers it, but a customer with a valid limit avoids it.
  • Add a new product: copy an existing file, give it a new name and code (the module code shown in Register One Step), and make a copy of a RUN-xxxx.bat with the new code.
EPLC and IWGT are switched off ("enabled": false). On DEV, "Advise LC One Step" needs an incoming LC (MT700) to pick from a catalog, and IWGT has no issue process in Register One Step. Put the right process and template in their files and set enabled to true, or record those flows (next section).

9. Record your own script

Playwright can watch what you do in the browser and write the script for you.

  1. Double-click RECORD-NEW-SCRIPT.bat.
  2. Type a name without spaces, for example EPLC_advise, and press Enter.
  3. Two windows open: Edge on the EximBill login page, and the Playwright Inspector, which shows the script being written as you click.
  4. Log in and do the steps in Edge, slowly, the way you normally would. Every click and every typed value is recorded.
  5. To add a check, click the eye / "Assert visibility" or "Assert text" button in the Inspector toolbar, then click the text on the page that must be there (for example "Transaction Completed").
  6. Close the Edge window when you are done. The test is saved as tests\recorded\EPLC_advise.spec.js. The password you typed is removed from the file automatically; it is asked again when you replay.
  7. To replay: double-click RUN-RECORDED-SCRIPT.bat, type the name (EPLC_advise), type the password. The window ends with PASSED or FAILED; SHOW-HTML-REPORT.bat shows the steps, and for a failure a screenshot and a trace (click it to replay the test action by action).
Tips for good recordings
- Start from the login page every time, so the script works on its own.
- Wait for each screen to finish loading before you click the next thing.
- A recording replays exactly the same values. If EximBill refuses duplicates (same customer, currency and amount), change the amount in the file before replaying, or use the product scripts (section 3), which pick a new amount every run.
- tests\recorded\EXAMPLE_login_and_enquiry.spec.js is a small example you can open with Notepad.

10. Change a script

Scripts are plain text files. Open them with Notepad, or better with Visual Studio Code (free) if it is allowed on the PC: right-click the file > Open with.

Change a recorded script

A recorded test (tests\recorded\<name>.spec.js) is a list of steps inside test('...', async ({ page }) => { ... });, one per line. The common lines:

Line in the scriptWhat it does
await page.goto('http://.../EximBillWeb/');Opens a URL. Change it for PRE-SIT, or use settings.url (below) so it follows settings.json.
await page.locator('input[name="WF_AMT"]').fill('123456');Types a value into a field. Change the text between the quotes.
await ....getByText('CONFIRM').click();Clicks something.
await ....selectOption('IPLC');Chooses a value in a drop-down list.
await expect(...).toContainText('Transaction Completed');A check: the script fails if the text is not there.
await page.waitForTimeout(5000);Waits 5 seconds. Add one after a slow screen if the next step fails.
page.locator('iframe[name="work"]').contentFrame() / frameLocator(...)The step happens inside an EximBill frame (work, eeinbox, eeToolbar). Keep these as recorded.

Delete a wrong step: delete its line. Add a step: easiest is to record the missing part as a new short script and copy its lines in.

Use the Excel test data in your own script (so you change values in Excel, not in the script). Add near the top:

const { row, settings } = require('../../framework/data');
...
const r = await row('IPLC-01');                        // the row with this Test ID
await page.goto(settings.url);                         // URL from settings.json
await work.locator('input[name="WF_CUST_ID"]').fill(r.customer);
await work.locator('input[name="WF_AMT"]').fill(String(r.amountFrom));

Find the name of a field or button

  1. Run RECORD-NEW-SCRIPT.bat (any name).
  2. In the Playwright Inspector click Pick locator (the target icon) and click the field on the page. The Inspector shows how to reach it, e.g. locator('input[name="WF_CUST_ID"]'). Copy that into your script.

Add or change a step in the middle of the flow (hooks)

The standard flow is: Register One Step → maker task (template, Fill, CONFIRM) → RFI / RFA → checkers → checks. When you need something extra in between (change a field on another tab, pick a different drop-down value, click a button, take a screenshot), you do not change the framework: you write a small hooks file for that product.

  1. Open the folder hooks. Copy _EXAMPLE.js and rename the copy to the module code: IPLC.js (or GTEE.js, IMCO.js ...). Use ALL.js for steps that apply to every product.
  2. Open it with Notepad. Keep only the hook(s) you need and delete the others:
    HookWhen it runs
    beforeRegisterConfirmRegister One Step is filled in, before its CONFIRM.
    afterRegisterRight after Register One Step (the new reference is in c.ref).
    beforeTaskA workflow task has just been opened (maker, RFI, RFA, checker), before anything is done on it.
    beforeConfirmThe task screen is ready (template and Fill values already in), before CONFIRM. This is the one you need most.
    afterTaskAfter the task was confirmed.
    afterChecksAfter the sanity checks of the transaction.
  3. Write the steps inside the hook. They are the same lines the recorder produces. On a transaction screen use work (the form), on the toolbar use toolbar: 
    async beforeConfirm({ page, work, task, c }) {
  if (task.name !== 'Issue Letter of Credit One Step') return;      // only on the maker screen
  await work.getByText('Shipment', { exact: true }).first().click(); // open a tab
  await work.locator('input[name="PORT_OF_LOAD"]').fill('JEBEL ALI'); // type in a field
  await work.locator('select[name="PARTIAL_SHIP"]').selectOption({ label: 'ALLOWED' }); // drop-down
},
  4. Get the lines from a recording: run RECORD-NEW-SCRIPT.bat, do only the extra clicks on the screen, close the browser, open the recorded file and copy those lines into the hook. Replace page.locator('iframe[name="work"]').contentFrame() (or page.frameLocator('iframe[name="work"]')) at the start of a line with work.
  5. Save and run the product as usual. The log shows hook IPLC.beforeConfirm (task name) each time a hook runs. If a hook fails, that step is reported as failed with a screenshot.

Values from the test data are in c: c.id, c.customer, c.amount, c.ref, c.fill, c.remarks. To control a hook from Excel, put a value in the Fill or Remarks column and read it in the hook, e.g. if (c.remarks.includes('NO-SHIPMENT')) return;

Which way to change something?
Different value in a field that the template already has → Fill column (Excel) or fill (module file).
A "... can't be empty" message → Defaults column.
Different customer, amount, template, process → the Excel row.
Extra clicks, another tab, a button, a check in the middle → a hooks file.
A completely different flow → record it as its own test (section 9).

Change how a product is created (no programming)

Most changes do not need code: change the process, customer, template, Fill or Defaults in data\testdata.xlsx or modules\<module>.json.

Debug a run step by step

Open a Command Prompt in the kit folder (type cmd in the Explorer address bar) and run:

set PWDEBUG=1
node\node.exe framework\run.js IPLC-01

The Playwright Inspector opens and stops before every action; press Step over to go one action at a time and see where it goes wrong. For a recorded test: node\node.exe node_modules\@playwright\test\cli.js test tests\recorded\<name>.spec.js --debug.

11. If something goes wrong

First look at the last lines of the black window or of the run-...log file, and at any error-...png screenshot in results\.

MessageWhat it means / what to do
[FAIL] Microsoft Edge does not startEdge is missing or blocked on this PC. Install / allow Microsoft Edge.
EximBill not reachable, ERR_CONNECTION, timeout on loginWrong url in settings.json, VPN / network, or EximBill is down. Open the URL in Edge by hand to check.
[W208] Invalid login credentials / login failed for ...Wrong user or password, or the user is locked. Check users in settings.json. For the RFA user, rfaFallbackToMaker: true uses the maker instead.
Database: ORA-01017Wrong database user or password.
Database: ... NJS-503 / connection refusedWrong connectString or no network to the database. Use the IP address, not the host name.
ORA-00942 table or view does not existThe database user cannot read the EximBill tables, or the schema names under database in settings.json differ in this environment.
registration failed: ... did not find some optionsThe process name in the module file is not in the Process Name list. Copy it exactly from Register One Step.
template ... not foundThe template name is not in the toolbar Load list. Pick an existing one.
screen errors: [W4206] ... can't be empty (keeps repeating)A mandatory field the template does not fill. Add it under defaults (by label) or fill (by field name).
task "..." for ... not in inboxThe task is assigned to another user or group. Check that the users in settings.json have the right groups.
Transaction LockedHandled automatically: the script unlocks it through <Product> > Unlock Transaction. If it still fails, unlock by hand.
authorization screen shows "no record"The validator cannot see the transaction for authorization (often user rights). Do the step by hand once to confirm.
ENQUIRY: View Transaction: [W215] No valid transaction records available!The enquiry itself fails for that transaction. This is an EximBill finding; report it.
EVENT STATUS: status PNot mastered within waitForMasteredMinutes. Look at the open tasks at the end of the log line, or raise the wait time in settings.json.
A step takes too long / timeoutEximBill is slow. Raise timeoutSeconds in settings.json (e.g. 120).
Stopping a run in the middle (closing the window) can leave a transaction locked or half way. Start RUN-EXISTING-REF.bat with its reference to finish it.

Useful facts about the EximBill screens

  • The page is made of frames: the left menu is in screen/index.htm, the inbox in frame eeinbox, the transaction form in work, the toolbar (CONFIRM, Load...) in eeToolbar, popups in *confirmDialogFrame. Use page.frameLocator('iframe[name="work"]') in your own scripts.
  • The fastest way to open any function is the menu Search box: type the function name and click "Module>Function".
  • The RFI / RFA decision popup is in the top page: comment box #decisionCommentText, buttons #decisionBtnApprove / "Submit Decision".
  • To step through a script slowly with the Playwright Inspector, run it from a command prompt in this folder: set PWDEBUG=1 then node\node.exe framework\run.js IPLC.
  • To record into the window yourself: node\node.exe node_modules\playwright\cli.js codegen --channel=msedge --target=playwright-test <url>.
  • To run all recorded tests: node\node.exe node_modules\@playwright\test\cli.js test tests\recorded (set EXIM_PASS first). The sanity test is started through the launcher (RUN-xxxx.bat), which picks the cases and asks the passwords.
  • Write a new test by hand: copy tests\recorded\EXAMPLE_login_and_enquiry.spec.js, and use require('../../framework/wf') for the EximBill steps (register, openTask, loadTemplate, makerConfirm, answerReferrals) and require('../../framework/db') for database checks.
